# FSIyagi — Windows·Linux 공용 파티션 (삭제 방지 파일시스템)

**한 파티션을 Windows 와 Linux 가 같이 읽고 씁니다.** NTFS·ext4·exFAT 를
대신하는 파티션 포맷입니다. 듀얼 부팅 PC 에서 두 OS 가 같은 원본 폴더를 보므로,
"어느 쪽에 최신 파일이 있더라" 하고 사본을 맞출 일이 없습니다.

| | NTFS | ext4 | exFAT | **FSIyagi** |
|---|---|---|---|---|
| Linux 에서 읽기·쓰기 | △ (ntfs3·ntfs-3g) | ✔ | ✔ | ✔ |
| Windows 에서 읽기·쓰기 | ✔ | ✘ | ✔ | ✔ (전용 드라이버, 드라이브 문자) |
| 저널링 (정전 대비) | ✔ | ✔ | ✘ | ✔ |
| 삭제 방지 | ✘ | ✘ | ✘ | ✔ |

그리고 이 파티션은 프로젝트 폴더를 실수로(또는 폭주하는 스크립트가) 지우지
못하게 합니다. 읽기·쓰기·생성은 전부 그대로 통과시키고 **삭제만 막습니다.**

```
os.remove()  shutil.rmtree()  find -delete  rm  perl unlink
                          │
                          ▼  전부 같은 시스템 호출로 모인다
                    unlink / rmdir
                          │
                    FSIyagi  ──▶  거부(EPERM)
```

어떤 언어·도구로 지우려 하든 커널의 같은 지점을 지나가므로, 거기서 막으면
빠져나갈 구멍이 없습니다. 명령어 이름을 검사하는 방식이 아니라서, 스크립트가
`rm`을 흉내 내거나 다른 이름으로 우회해도 똑같이 막힙니다.

또한 삭제 없이 내용만 지우는 경우(`> file.cpp`, 편집기 저장 중 실수 등)를
막으려고, 파일이 **덮어써지기 직전**의 내용을 한 벌 따로 보관합니다(Vault).

## 설치

### Linux

deb 패키지를 받아 설치합니다:

```bash
sudo dpkg -i fsiyagi_*.deb
sudo apt --fix-broken install   # 의존 패키지가 빠졌다면
```

설치 직후에는 아무것도 자동으로 켜지지 않습니다. 마운트 지점을 스스로
정할 수 있게, 서비스도 수동으로 켜야 합니다.

### Windows

설치 파일(`FSIyagi_Setup_v*.exe`, 관리자 권한)을 실행하면 FSIyagi 드라이버가
들어갑니다. 그 뒤 `fsiyagi-manager` 에서 FSIyagi 파티션에 **드라이브 문자**를
지정하면 NTFS 드라이브처럼 탐색기에 나타나고, 문자는 Windows 가 기억하므로
다음 부팅부터는 저절로 붙습니다.

삭제 권한은 Linux 의 `fsguard` 그룹 대신 Windows 로컬 그룹 **"FSIyagi Guard"** 가
맡습니다. 설치할 때 그 그룹을 만들고 지금 로그인한 사용자를 넣어 둡니다.
Windows 에서 열 수 있는 것은 **NATIVE MODE** 로 포맷한 파티션입니다(아래 "두 가지
저장 방식" 참고).

## 첫 사용

### 1. 삭제 권한을 받을 계정을 그룹에 넣는다

`fsguard` 그룹에 속한 프로세스만 삭제할 수 있습니다. 그 밖에는 파일을
지우려는 모든 시도가 거부됩니다 — 관리자 계정도 예외가 아닙니다.

```bash
sudo gpasswd -a "$USER" fsguard
```

**재로그인해야 반영됩니다.**

### 2. 관리 UI로 파티션을 준비한다

```bash
fsiyagi-manager
```

디스크 목록에서 파티션을 골라 **포맷**하고 **마운트**합니다. 처음 켤 때는
기존에 쓰던 검증하지 않은 파티션 대신, 비어 있거나 지워도 되는 파티션으로
시작하는 것을 권합니다.

### 3. 평소처럼 쓴다

마운트한 지점 안에서는 파일 만들기·수정·빌드가 전부 평소와 똑같이
작동합니다. 다른 점은 딱 하나, **지우려고 하면 거부된다**는 것뿐입니다.

```
$ rm important.txt
rm: cannot remove 'important.txt': Operation not permitted
```

정말로 지워야 할 때는 `fsiyagi-admin`으로 `fsguard` 그룹 권한을 명시적으로
빌려 실행합니다:

```bash
fsiyagi-admin run rm important.txt
```

### 4. 관리 UI로 상태를 확인한다

`fsiyagi-manager`의 **디스크** 탭에서 사용량·마운트 상태를 보고, **도구** 탭에서
Vault(보존된 원본)를 찾아 되살리거나, 정책을 조회하고, 필요하면 포맷을
되돌릴 수 있습니다.

## 두 가지 저장 방식

| | EXT4 MODE | NATIVE MODE |
|---|---|---|
| 저장 형식 | 표준 ext4 위에 얹음 | 자체 온디스크 포맷 |
| 복구 | 기존 ext4 도구로 가능 | 전용 fsck 필요 |
| 용도 | 호환성·기존 환경 | 성능·완결성 |
| Windows 에서 열기 | ✘ | ✔ |

마운트할 때 어느 방식을 쓸지 고를 수 있습니다. 어느 쪽이든 삭제 방지
정책은 같은 코드를 공유하므로 동작은 동일합니다.

## 언어

시스템 언어를 따라 자동으로 표시됩니다. 지원 언어: 한국어, English, Deutsch,
Español, Français, Bahasa Indonesia, 日本語, Português, Русский, Türkçe,
Tiếng Việt, 中文. 다른 언어로 강제 전환하려면 설정 파일에
`ui/language=<코드>`를 추가하십시오(예: `en`, `ja`).

## 문제 해결

**`Operation not permitted`로 삭제가 안 된다**
의도된 동작입니다. `fsiyagi-admin run <명령>`으로 실행하거나, 계정이
`fsguard` 그룹에 있는지(`groups` 명령으로) 확인하십시오.

**마운트 지점이 빈 화면으로 보인다**
마운트 지점에 원래 내용이 있었는데 대상 파티션이 비어 있으면, 실수로
내용을 가리는 사고를 막기 위해 마운트 자체가 거부됩니다. `fsiyagi-manager`에서
올바른 파티션을 선택했는지 확인하십시오.

**`Transport endpoint is not connected`**
데몬이 죽었습니다. 언마운트 후 다시 마운트하십시오.

**포맷 전 데이터를 되돌리고 싶다**
포맷할 때 "되돌리기용 백업" 옵션을 켰다면, `fsiyagi-manager`의 도구 탭에서
포맷을 되돌릴 수 있습니다. 데이터 영역은 건드리지 않으므로 포맷 이후에
새로 쓴 내용만 없으면 원래 파일시스템이 돌아옵니다.
